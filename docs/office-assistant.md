# Office 助手

本次接入目标版本为 0.9.9，上游固定为 Office 助手 v1.9.2（`d1e3ec88fb3366a39200ee1c4a909edc2f51388e`）。源码和逐文件指纹见 `runtime/astrbot_plugin_office_assistant`、`release/native-plugin-sources.json`；微信适配保留为独立补丁。

## 使用

1. 在功能中心打开 Office 助手，保留现有支持工具调用的聊天模型。
2. 默认只有机器人管理员和用户白名单可用。需要开放时，在功能中心填写微信用户 ID；“允许所有用户”按需开启。
3. 私聊说“帮我生成一份 Word 周报”“整理成 Excel”或“制作基础 PPT”，生成后会发回文件。
4. 上传文件后用 `/doc list` 查看文件编号，再用 `/doc use 文件ID 处理要求` 继续处理。群聊先在群聊管理允许 Office 助手，处理请求需 @ 机器人；同一用户上传后的短时间内发出 @ 请求也会合并处理。
5. 图片先发送，再用 `/img add 图片用途` 登记；可用 `/img list`、`/img use` 选择素材。

默认大小上限 20 MB，上传会话保留 10 分钟。生成文件默认保留，避免微信接口接受请求后仍在读取文件而被提前清理；用 `/list_files` 查看，用 `/delete_file 文件名` 清理。文件按用户和会话隔离。

## 能力边界

- Word、基础 Excel、基础 PPT 可直接使用随完整载荷提供的依赖，不要求客户安装 Node。
- PDF 内容提取及 PDF 转 Word/Excel 已包含 Python 依赖；扫描件和复杂表格不保证还原效果。
- Office 转 PDF 仍需要客户机器上的 Microsoft Office 或 LibreOffice；用 `/pdf_status` 查看可用性。Java 是 tabula 表格提取后端的可选条件。
- 复杂 Excel 的本机脚本执行默认关闭，普通用户不需要开启。普通表格生成和读取不受影响。
- 未授权用户的文件不会被本插件主动缓存。群聊开关、群功能范围和用户白名单同时生效。

## 开发与交付

复用原插件的结构化文档/工作簿工具、导出、权限和会话存储，复用桥接的文件下载和发送接口。微信附件保留安全文件名、扩展名，并等待下载完成；AstrBot 仅对 `aiocqhttp_hook41827` 接受本地文件 URI，不改变其他 OneBot 平台的 HTTP/文件 ID 路径。

完整载荷暂存阶段会自动执行 `build_office_renderer.py`，按上游 npm lock 安装依赖、编译并移除仅构建所需的类型声明。管理器把已有 Playwright Node 目录加入服务 PATH。Python 新增依赖使用现有锁定 wheelhouse 校验流程；本任务未执行完整载荷构建、安装或线上发布。

本次修改 Python 依赖锁及 AstrBot 核心补丁，必须使用完整载荷更新。取得本次完整载荷确认后，使用桌面“本地打包完整载荷”入口；不要使用管理器增量或组件增量替代。本机依赖缓存也须匹配更新后的 `release/runtime-wheelhouse.json`。

## 用户侧验收

- 管理员私聊生成中文 Word、Excel 和 PPT，确认微信收到后能打开。
- 上传同名的两份文件，分别选择处理；文件内容和目标用户应对应。
- 群聊上传后 @ 机器人处理；另一用户不能读取前一用户的文件。
- 关闭该群 Office 助手或移除用户授权，确认命令和文件处理被拒绝。
- 尝试超限文件、下载中断及缺少 Office/LibreOffice 的 PDF 转换，确认不会宣称成功。
- 本地离线生成和模拟回传通过，不代表以上真实微信验收已完成。
