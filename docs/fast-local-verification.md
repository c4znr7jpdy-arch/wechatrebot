# 快速验证 Bug 修复

日常循环：修改源码 → 本次改动的定向测试 → 源码窗口验证。安装环境可一直保留；确认要分发或验证安装行为时再构建包。

## 管理器和内置界面

在正在修改的仓库中运行：

```powershell
.\scripts\dev-manager.ps1
```

脚本从安装位置记录读取现有安装目录，复用本仓库已有的 Python 3.13 管理器构建环境。它不下载依赖、不冻结 EXE、不生成载荷、不执行安装。若安装位置记录缺失，可用 `-InstallRoot '实际安装目录'` 指定；`-Python` 可指定已有 Python 环境。

运行前从托盘退出已打开的管理器；机器人服务可以继续运行。同一安装目录仍使用同一把单实例锁，开发工具不会强行终止已有管理器。源码窗口标题带 `[源码验证]`，窗口关闭即退出。它跳过安装入口、卸载注册、快捷方式和旧更新文件清理。

管理器读取本仓库 `src/wechatrebot_manager` 的代码和界面资源。保存这些文件后，监听器自动重启自己启动的管理器窗口；不会替换已安装的 EXE，也不会主动启停机器人服务。窗口中的设置、服务启停等操作仍作用于真实安装环境。自动重启会丢失尚未保存的表单，可添加 `-NoWatch` 并在保存设置后手工重开。独立的插件配置窗口修改后需要关闭重开。

添加 `-Check` 只检查解释器、安装标记和源码路径，不打开窗口。

## 只验证界面

```powershell
.\scripts\dev-manager.ps1 -Preview
```

浏览器使用现有示例数据展示页面，保存 HTML/CSS/JS 后自动刷新。仅监听本机回环地址；Ctrl+C 关闭。此模式不需要已安装机器人，也不能用于判断真实回复、数据持久化或插件是否生效。`-NoBrowser` 可只打印地址供手工打开。

## 插件和运行时

修改本仓库 `vendor/` 固定输入、`runtime/` 或 `patches/` 不会自动改变已安装插件。先完成定向测试，再备份并仅同步本次插件改动到实际安装目录，通过现有插件重载接口重载目标插件，复查生效配置和日志，最后发送对应测试消息。涉及共享引擎代码或不支持重载的插件时，只重启所需服务。此入口不自动同步插件、重启微信或修改 hook。

需要验证冻结 EXE 的资源收集时，只构建管理器。需要验证安装/修复/升级/卸载逻辑时，在独立测试目录运行安装器；常规 Bug 验证不需要先卸载当前软件。完整离线包留到分发验收时生成。
