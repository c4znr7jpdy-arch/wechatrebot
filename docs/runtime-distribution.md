# 应用与运行环境分离

目标版本：1.0.30。应用使用完整应用包更新，Python、全部 Python 依赖和 FFmpeg 使用独立、带签名的环境清单。更新类型属于完整应用更新，不再要求客户端依次安装中间版本。旧的完整载荷、管理器增量和组件增量读取能力保留，用于历史版本迁移与回滚。

## 用户流程

- 新安装只安装管理器、业务引擎、插件、资源和内置页面。进入运行中心后，点击一次“安装运行环境”，统一安装依赖和音视频工具。
- 安装期间显示当前阶段和进度；失败后可重试，已完整下载且校验通过的包从缓存复用。尚未完成的单个包重新下载，不承诺 HTTP 断点续传。
- 环境准备完成前不能启动机器人或连接授权微信。功能中心不增加逐个插件的环境按钮，也不增加组件管理页面。
- 后续更新下载目标版本的完整应用，检查该版本的完整环境清单，只补齐缺少或内容变化的包。先准备全部所需文件，确认停止机器人后，在同一个可回滚事务中切换应用和环境。
- 新管理器每次启动在后台校验环境一次，状态轮询复用检查结果。安装时、更新交接后会再次校验；不会仅凭“已安装”标记跳过摘要检查。

## 文件与版本边界

| 内容 | 位置 | 更新策略 |
| --- | --- | --- |
| 管理器、插件、桥接、页面、资源 | `manager/`、`app/` | 每次完整应用更新 |
| AstrBot 业务核心、共享授权逻辑 | `app/engine/python/` | 从固定 wheel 重建并应用当前补丁，随应用更新 |
| Python、第三方 Python 包 | `runtime/python/` | 按内容指纹复用 |
| FFmpeg、FFprobe、随附 DLL 和许可证 | `runtime/ffmpeg/` | 一组独立环境包 |
| 已签名的目标环境清单 | `legal/runtime-environment.json` | 随应用固定，不追逐远端 latest |
| 完整下载缓存 | `cache/runtime-packages/` | 以压缩包 SHA-256 命名，失败重试可复用 |

用户只看到一套运行环境。内部按 Python 基础文件、FFmpeg、第三方包目录和小型元数据分组；增加一个依赖不会让所有旧包的指纹变化。环境 ID 包含平台、Python ABI 和完整目标文件清单，独立于应用版本。客户端不运行 pip，不动态解析依赖版本。

每个清单固定下载 URL、文件列表、大小和 SHA-256，并使用现有 Ed25519 发布密钥签名。下载包也有摘要和大小校验。路径必须位于受管目录，拒绝重复路径、目录冲突、链接、越界以及混入业务引擎代码。新环境的全部文件都校验成功后才安装。

旧文件只从已安装的受管文件记录中清理。用户配置、数据库和用户目录保留；旧程序文件如果被用户修改，清理会停止并报错。环境安装与应用更新共用进程锁，环境操作还占用管理器的更新锁和启动操作锁。

## 后续发布与新增依赖

统一入口仍为 `scripts/publish-github-release.ps1`。默认选项为完整应用；普通更新复用发布成功后保存的 `artifacts/runtime-environment/latest.json`，不重建或扫描完整 Python 环境。新安装器仍通过标准 Inno Setup 生成。

首次拆分选择已经通过锁定验证的运行环境构建目录。发布工具生成环境包、完整应用包和在线安装器，所有资产仍发布到 GitHub Releases。环境包文件名使用内容指纹；未变化的包保留原版本 URL，不重复上传。历史环境资产不得删除，否则依赖它们的旧应用无法安装或恢复。

新增依赖时先更新依赖锁、wheelhouse 指纹和相应许可证记录；选择“重建环境”后，统一入口调用现有运行时构建工具，再比较内容指纹，仅生成变化的环境资产。该操作需要明确选择并确认，依赖锁不匹配时不会暗中回退为完整构建。日常业务补丁和授权逻辑修改不需要重建环境。

候选记录保存完整资产清单，可沿用原有恢复上传流程。稳定清单切换前校验新资产和复用的历史环境资产，检查应用内的环境清单与发布引用一致；网络校验失败则不切换 stable。回滚应用版本时保留历史环境资产，沿用目标版本绑定的环境清单。

## 首次迁移的边界

1.0.29 等旧管理器不认识分离式事务。首次升级可能由旧更新器先替换应用，再由新管理器检查和补齐环境；新管理器会在环境就绪前拦截启动。已有兼容环境会被复用，但不能声称旧更新器也具备新的应用/环境联合事务能力。需要严格保证第一次迁移也使用联合事务时，应先发布支持本协议的管理器过渡更新。

新协议管理器之间的跳版本升级使用目标版本完整清单，无须经过中间应用或环境版本。中断的独立环境安装会在运行中心显示重试入口；重试先恢复旧文件，再继续安装。恢复失败时保留回滚记录，禁止带着未确认的环境启动。

应用包不保证只有管理器的三十多 MB：插件、业务引擎及资源仍占空间。最终压缩大小以实际候选构建为准。首次环境下载的成本仍然存在，减少的是普通应用更新时的重复下载。

## 验证边界

本次使用小型签名测试包验证下载、复用、签名/路径拒绝、跳版本、删除旧依赖、失败回滚、进程锁和独立 Python 导入；通过页面预览验证安装、失败、重试和就绪状态。未启动机器人，未执行正式运行时构建、客户安装器构建、发布或真实微信验收。实际干净 Windows 安装、旧客户迁移及完整环境性能仍需发布前验证。
