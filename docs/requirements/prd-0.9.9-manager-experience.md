# WeChatReBot 0.9.9 管理器体验 PRD

> 文档状态：基于当前仓库版本整理的产品需求基线  
> 基线版本：0.9.9  
> 目标用户：非技术群主、机器人运营者、个人微信用户  
> 主要入口：Windows 管理器

## 1. 背景与问题

现有需求按插件、缺陷和专项能力分别记录，用户实际遇到的问题却跨越多个页面：不知道机器人是否准备好，不清楚某个群会收到什么消息，回复变慢时看不懂原因，模型、人格、记忆和主动推送的开关彼此分散。部分旧需求还把“已安装”当成“可使用”，或把历史技术实现直接暴露给客户。

用户真正要完成的是：

> 我想选定一个微信账号和几个群，明确机器人在这些地方做什么、什么时候会主动发消息，保存后能确认已经生效；出现问题时，我能知道下一步怎么处理。

## 2. 产品目标

### 2.1 目标

1. 用户首次打开管理器即可判断微信、模型、目标群和核心功能是否准备好。
2. 所有按群发生的行为在“群聊&私聊管理”中可找到，包括回复方式、功能范围、主动推送、安静时段和任务。
3. 人格、情感、长期记忆和回复节奏使用客户能理解的概念，并能分别预览、保存和回读。
4. 定时任务以“做什么、发给谁、什么时候”统一管理，避免命令、插件和任务三套入口互相覆盖。
5. 配置成功以在线热更新后的服务端回读为准；离线时明确显示“下次启动使用”。

### 2.2 成功指标

- 新用户从首次打开到完成一次点名回复测试，不需要阅读技术文档或输入群 ID、Cron 表达式、插件名。
- 已打开过的功能和群详情再次进入时不出现整页闪白，未保存草稿不被后台刷新覆盖。
- 用户能在 30 秒内回答“这个群会不会收到主动消息、下一次何时发送、为什么没发送”。
- 配置保存后的成功提示与实际回读一致；失败时保留原配置或可恢复草稿。
- 所有主动发送均能追溯到具体群、任务或用户操作，不因升级、新安装或重复点击产生隐藏任务。

## 3. 用户与使用场景

### 3.1 主要角色

| 角色 | 目标 | 关键约束 |
|---|---|---|
| 群主/群管理员 | 控制本群的机器人行为 | 机器人账号不一定是群主；微信未返回权限时按未知处理 |
| 机器人运营者 | 管理模型、功能、任务和故障 | 需要看到跨群配置与运行结果，但不应暴露密钥和内部模块名 |
| 私聊用户 | 管理自己的私聊体验 | 只能看到自己有权管理的会话任务 |

### 3.2 核心场景

- 新安装：完成“开始使用”清单，选账号和群，配置回复模型，知道下一步如何安全测试。
- 日常调整：打开某个群，修改回复方式或允许功能，保存并确认热更新结果。
- 主动消息：建立一项天气、资讯、文字提醒或影视推荐任务，选择多个群/联系人，预览后启用。
- 回复变慢：查看最近一次回复的白标链路，知道耗时在模型、记忆、语音还是发送阶段。
- 数据控制：区分聊天记录副本、近期上下文、长期记忆和外部账号数据，分别导出或清理。

## 4. 产品原则

1. **以会话和结果组织界面**：客户看到群、联系人、任务和结果，不需要先理解插件。
2. **状态真实可解释**：未知、离线、待配置、被群策略拦截和发送失败必须区分。
3. **保存与生效分离**：草稿可以保存，生效必须经过热更新或明确标记为下次启动使用。
4. **默认安全**：新群默认仅响应点名，不主动推送；新安装不创建业务任务。
5. **白标表达**：不展示 AngelHeart、Mnemosyne、AstrBot 等内部实现名，不在普通日志暴露提示词、密钥、完整路径和消息正文。
6. **单一长期记忆口径**：产品只提供一个“长期记忆”概念，同一会话不得由两套长期记忆同时处理。

## 5. 信息架构

保留并强化以下一级入口：

- **开始使用**：准备检查、首次配置和可再次进入的引导。
- **群聊&私聊管理**：群/联系人目录、按会话的机器人策略、主动消息授权、安静时段和任务入口。
- **消息中心**：聊天记录副本、实时消息、会话搜索和数据清理入口。
- **功能中心**：以用户任务分类展示功能，显示可用性和依赖，不以“已安装”代替可用状态。
- **模型与服务**：聊天、图片、向量、语音服务分别管理；只展示用户已配置或明确可用的服务。
- **人格与记忆**：称呼、语气、情感、回复节奏、长期记忆和隐私控制。
- **定时任务**：统一创建、编辑、启停、复制、删除和执行记录。
- **运行记录**：白标回复链路、配置变更和任务结果。

## 6. 需求范围与优先级

### 6.1 Must：本轮必须交付

#### M-01 开始使用与准备检查

- 首次打开显示可跳过、可再次进入的检查清单：微信登录、机器人账号、回复模型、目标群、核心功能。
- 每项显示“可直接使用、还需配置、外部服务离线、当前群未启用、存在风险”之一，并给出下一步。
- 检查只读，不自动启动机器人、不发送测试消息、不改变群策略。
- 完成后提示“可在选定群里点名机器人测试”。

#### M-02 群聊&私聊管理

- 从当前登录账号的只读目录读取群和联系人；显示名称、稳定标识、实际返回的头像和可用权限信息。
- 刷新失败保留同账号最后成功数据并标记未更新；账号变化立即清空旧账号数据；空结果不能伪装成“0 个群聊”。
- 群详情集中管理：机器人总开关、回复方式、允许功能、主动推送、安静时段、每日上限和定时任务。
- 选择进入草稿；保存前展示影响范围，保存后热更新并回读。
- 群主/管理员未知时显示“未知”，涉及管理写操作默认拒绝。

#### M-03 人格、情感与长期记忆

- 群聊与私聊可分别配置称呼、语气、回复长度、主动程度、情感强度和边界。
- 长期记忆、情感变化、回复节奏独立开关，并解释关闭后的行为。
- 提供不发送到微信的预览，明确是否使用近期上下文、长期记忆、表情和语音。
- 记忆数据控制区分聊天记录副本、近期上下文、长期记忆和外部账号数据；删除前说明不可恢复范围。

#### M-04 回复链路与速度解释

- 最近一次回复显示：收到消息、决定回复、记忆、模型、表情/语音、发送完成及各阶段耗时。
- 明确点名、引用和唤醒类消息走快速路径；可选阶段超时后降级继续回复。
- 显式回忆请求优先尝试长期记忆；记忆关闭或超时要说明实际降级方式。
- 日志不含消息正文、密钥、完整提示词和内部品牌名。

#### M-05 统一定时任务

- 所有具备明确参数、结果和发送语义的用户命令都可以转换为定时任务；天气、资讯、油价、影视、签到、查询和文字提醒不再按固定白名单分期限制。
- 命令进入定时任务前必须声明可定时化信息：用户可填写的参数、所需功能或账号、允许的收件人类型、是否会产生外部写操作、结果展示方式和失败处理方式。
- 需要临时追问、扫码/验证码、上下文引用、实时人工确认或执行任意脚本的命令，不得直接创建为定时任务；应显示不可定时原因和替代入口。修改外部系统状态的命令可以定时，但必须在创建时单独授权，明确影响、账号、频率、重复执行保护和撤销方式。
- 支持从命令识别进入可编辑草稿，也支持从任务编辑器按用户可见命令名选择；不得要求用户输入插件名、内部命令名或 Cron 表达式。
- 收件人支持群聊/私聊混合多选；默认不选；任务绑定稳定账号和聊天标识。
- 支持仅一次、每天、每周；明确北京时间和未来三次执行时间。
- 提供预览、保存草稿、创建并启用、暂停、恢复、复制、删除和按对象执行记录。
- 每次执行按任务保存参数快照，不能在运行时重新理解原始自然语言；命令定义或功能配置变化时标记任务需要检查，不静默改变行为。
- 发送失败按对象隔离，重试不重复发送成功对象；结果未知时标记待确认。任务自身执行失败、部分对象发送失败和被群策略拦截必须分别显示。
- 执行前重新检查账号、权限、功能依赖、费用风险和外部写操作授权；缺少依赖或授权失效时跳过本次执行并给出可操作原因，不自动切换到未配置或可能收费的服务。
- 同一任务不得因多个入口或重复点击生成重复计划；升级时迁移已有有效任务并保留原参数、目标、时区和启停状态。
- 新安装零任务；启用功能、读取配置、升级和进入页面均不得自动创建业务计划。

#### M-06 模型服务闭环

- 服务分类明确区分聊天、图片、向量和语音；不展示工厂/共享主密钥服务作为客户可配置项。
- 用户服务可删除；当前回复模型或被功能引用时先列出引用并要求迁移。
- 兼容模型列表接口时可用未保存的地址和密钥拉取列表；失败提示区分鉴权、超时、不兼容和空列表。
- 保留手动填写模型名；拉取列表不得覆盖用户当前选择。
- 密钥默认隐藏，日志、错误和诊断不得回显。

### 6.2 Should：完成 Must 后交付

- 备份与恢复进入统一控制台：恢复前校验版本与内容，自动创建恢复点。
- 管理员与权限中心：显示机器人管理员、群管理员和普通成员的可确认范围，记录高风险操作。
- 主动消息总控：集中暂停全部主动消息，区分定时任务与 AI 主动聊天。
- 用量、额度与降级提示：只展示用户可行动的可用性，不暴露发行方主账号和成本。
- 一键诊断包：用户确认内容后导出，不含正文、密钥、Cookie、完整路径和内部品牌。

### 6.3 Could：验证后再做

- 家庭群、兴趣群、工作群、客服群模板。
- 每周机器人使用摘要、点名次数和失败率。
- 多套人格按群切换。
- 移动端伴侣 App。

### 6.4 Won't：当前明确不做

自动踢人/禁言/编辑群公告、绕过微信权限、代绑第三方账号、代输入验证码、补拉安装前或离线期间的完整历史、任意脚本/自动改代码、高风险自动改代码能力的普通客户入口，以及把客户端变成本地短剧播放服务器。

## 7. 关键流程

### 7.1 首次可用

打开管理器 → 查看准备检查 → 登录/确认账号 → 选择目标群 → 配置聊天模型 → 查看核心功能状态 → 进入群详情 → 看到“点名测试”说明。

### 7.2 群策略变更

打开群详情 → 修改策略进入草稿 → 预览“会回复什么/会不会主动发消息” → 保存 → 在线热更新 → 回读服务端配置 → 展示生效时间与失败处理。

### 7.3 创建定时任务

选择动作 → 填写动作参数 → 选择群/联系人 → 选择一次/每天/每周与时区 → 预览内容和未来三次执行 → 保存草稿或创建并启用 → 在任务详情查看逐对象结果。

### 7.4 故障定位

打开运行记录 → 按会话或任务筛选 → 查看阶段耗时与状态 → 跳转到缺失配置、群策略或模型服务 → 修复后重新读取/重试。

## 8. 验收标准

- 新安装完成后功能中心和定时任务均不生成虚假业务数据。
- 同一账号的群目录、消息中心和任务收件人使用一致的稳定标识；切换账号不串数据。
- 后台刷新、快速切换页面和离线重连不会覆盖未保存草稿或显示其他功能内容。
- 每个保存成功提示都能在回读结果中找到对应值；热更新失败时原值仍可恢复。
- 普通用户无需输入插件名、群 ID、Cron 表达式或 `/sid` 即可完成核心流程。
- 每个用户可见命令都能明确显示“支持定时 / 需要补充条件 / 不支持定时”及原因；支持定时的命令可以从命令入口和任务中心创建同一类任务。
- 任意可定时命令创建后，任务详情都能展示参数快照、依赖、目标、下一次执行时间、预览内容和逐对象结果；命令升级不会静默改写已保存参数。
- 需要交互、验证码、上下文或外部写操作的命令不会被误加入计划；界面提供安全替代动作或明确说明只能手动执行。
- 任何主动消息均能回答“由哪项任务/授权产生、发给谁、何时执行、结果如何”。
- 运行记录和诊断材料不会泄露密钥、消息正文、私人记忆、Cookie 或内部实现名。

## 9. 版本计划

1. **0.9.9 基线整理**：以当前已实现的群目录、聊天记录、模型服务、功能中心加载体验和主动消息策略为事实基础，补齐本 PRD 的统一术语和验收口径。
2. **下一迭代 P0**：M-01 准备检查、M-02 群中心、M-03 人格/记忆、M-04 回复链路。
3. **下一迭代 P1**：M-05 统一任务编辑器、M-06 模型服务完整闭环。
4. **维护迭代**：Should 项，按真实使用数据决定顺序；Could 项不得提前挤占 P0/P1。

本 PRD 只定义产品目标和验收边界，不代表上述未完成能力已经进入安装包或线上发布。实现前仍需以当前源码、桥接接口和安装运行时分别核验。

## 10. 待确认决策

1. 新群默认是否长期保持“仅响应点名”，还是由群主首次进入时显式启用机器人。
2. 长期记忆是否继续由当前单一实现承载，迁移期间如何清理旧安装的遗留数据。
3. 首期统一任务动作清单中，热点资讯和影视推荐的外部来源与内容授权是否已满足交付条件。
4. 群目录接口能稳定返回哪些权限字段；未返回的角色信息继续按未知处理。
