# 本地增量更新

已有完整安装后，日常修改无需反复打包整套运行环境。目标版本仍从 `pyproject.toml` 读取（当前 0.9.9）。开发者入口为 `scripts/update-local-incremental.ps1`，桌面“本地增量更新”快捷方式可直接调用它。

## 日常操作

先完成代码提交、验证并合入远端 `master`，同步本地 `master` 工作树，再停止机器人；管理器也有修改时先关闭管理器窗口。双击桌面“本地增量更新”。入口自动定位当前安装，核对底层组件与安装清单，组装源码、应用项目适配补丁、检查敏感文件，生成差异包并事务安装。默认插件源码目录沿用 `E:\Project`，只读取 `release/source-manifest.json` 指定的条目。

只修改插件时不编译管理器；管理器源码、依赖锁或构建脚本变化时才构建管理器。首次使用时缺少管理器构建输入记录，也会构建一次管理器，以交付新的更新器。不会重建、遍历或打包 Python 与 FFmpeg。只有管理器变化时，可使用入口的 `-ManagerOnly` 选项，跳过插件组装和底层兼容检查。

`-Plan` 只做更新范围和兼容基线预检，不构建、不安装，也不提供最终字节差异统计。`-PackageOnly` 完成差异包但不安装。入口需要开发环境 Python 3.13；它不会上传、发布或启动机器人。安装后由维护者手动运行验证。

结果保存在本次 `artifacts/local-incremental-时间/`：`incremental.zip`、`update-report.json` 和必要的构建日志。成功后清理源码暂存、重复的管理器编译产物及安装临时解包文件；可复用的管理器编译环境保留。失败时保留诊断，不自动启动完整载荷构建。

## 适用范围

| 修改 | 更新方式 |
| --- | --- |
| 命令、新闻、帮助、定时任务处理代码、插件 Python/资源 | 组件增量 |
| 新增且依赖已满足的插件 | 适配并加入源码清单后，组件增量 |
| 管理器和内置界面 | 管理器增量 |
| Python、FFmpeg、依赖锁、AstrBot 核心补丁、hook DLL | 完整载荷，仍需单独确认 |

从 AstrBot 市场引入插件时，先在项目中完成平台兼容、命令/配置/定时任务适配，更新插件与源码清单并做定向验证。新增文件不局限于固定插件名单。构建器检查声明的 Python 版本和依赖是否被已安装的锁定运行时满足；新增依赖、动态依赖或无法验证的声明会拒绝。它不会运行 pip，也不能代替插件行为兼容验证或自动完成所有市场插件适配。

## 安装与回滚

差异包记录新增/修改文件的 SHA-256、受管废弃文件及其旧 SHA-256，以及安装基线指纹。安装前后均核对基线，拒绝覆盖本地改写的受管文件或同名的未登记文件。删除仅覆盖旧安装清单登记的文件；不会清空任意插件目录。用户配置、账号数据、命令配置和其他未受管数据保留，因此插件自行生成的缓存不会被猜测删除。

修改运行时代码或资源时必须停止机器人；入口只检查状态，不强制结束进程。事务备份只含本次涉及的文件、删除项和安装标记，失败恢复文件与原清单。增量安装成功后将变化合入完整安装清单，下一次继续计算差异。

## 在线更新边界

本地 `incremental.zip` 是根目录载荷，不能直接作为在线下载包。现有 `build_update_release.py` 已支持读取它并封装成 `payload/` 结构，保留 schema 2、基线指纹与删除项，再签名；schema 2 不允许使用 `--include` 截断操作集。该能力仅负责构造更新产物，本地入口不调用它或任何发布脚本。

旧管理器仅识别 schema 1，先用原有管理器增量路径升级更新器，再交付组件增量。新组件包绑定具体基线；不匹配会安全拒绝，当前没有自动追补多版本链或按客户基线选择线上包。发布时须准备对应基线，或继续使用既有完整更新路径。不得把本地端到端测试当作旧客户端迁移和线上部署已完成的证明。
