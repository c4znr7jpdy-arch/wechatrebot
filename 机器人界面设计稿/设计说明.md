# 姜小妹机器人界面设计稿

本套设计稿基于当前项目的 `DESIGN.md`、`UX-CONTRACT.md`、现有管理器 Web UI 和真实功能清单制作。目标用户是第一次接触微信机器人的普通 Windows 用户、群主和社群运营者。

## 设计目标

- 先显示“能不能用”和“下一步做什么”，再显示技术细节。
- 保留现有 7 个主页面和全部业务能力，不改变功能语义、数据来源或安全边界。
- 页面中统一使用“机器人、微信连接、功能、群聊、聊天记录、定时任务、运行记录”等用户语言。
- 主操作只保留一个明显入口；危险操作使用红色并二次确认。
- 默认配置采用保守策略：新群只在被点名时回复、默认不主动推送、普通用户优先使用推荐模型。
- 状态同时使用颜色、图形和文字，避免只依靠颜色判断。

## 信息架构

| 主页面 | 设计稿覆盖 | 核心任务 |
|---|---:|---|
| 运行中心 | 3 个状态 + 1 个窄屏 | 查看机器人是否可用、启动、停止、解决微信环境问题 |
| 功能中心 | 3 个页面 + 1 个下拉 + 1 个窄屏 | 搜索功能、启停、填写常用设置、保留专业设置 |
| 群聊管理 | 3 个页面 + 1 个下拉 | 刷新群聊、复制群标识、查看成员、配置群规则 |
| 聊天记录 | 2 个页面 + 1 个日期选择器 | 分类筛选、搜索、查看消息、导出、删除本机副本 |
| 定时任务 | 1 个页面 + 2 个弹窗 | 查看业务任务、暂停、改时间、删除 |
| 运行记录 | 1 个页面 | 查看脱敏的回复链路和生命周期记录 |
| 设置 | 4 个页面 + 5 个弹窗/下拉 | 模型、人格、记忆情感、品牌身份、微信路径、维护更新 |

## 弹层清单

1. 首次使用引导
2. 未保存设置离开确认
3. 功能配置选择群聊
4. 删除聊天记录
5. 修改定时任务时间
6. 删除定时任务
7. 删除模型服务并选择接替模型
8. 创建设置与记忆备份
9. 恢复备份并选择备份版本
10. 按日期清理聊天记录
11. 发现新版本
12. 更新下载与校验进度

下拉和系统弹层另行覆盖：模型服务类型、模型名称建议、群聊回复方式、人格语气、功能选项、日期选择器，以及成功/离线/失败三种 Toast 反馈。

## 易用性策略

- 页面标题下方用一句话解释用途，不展示底层框架、桥接、端口或内部模块名。
- 运行中心使用三阶段轨道：微信环境 → 机器人功能 → 消息连接。
- 功能中心采用“左侧选功能、右侧看说明和设置、底部固定保存”的结构；修改失败时保留输入。
- 群聊管理把“读群列表”和“向群发消息”明确区分，降低用户误操作焦虑。
- 聊天记录持续说明“只是本机副本”，删除不影响微信原记录或长期记忆。
- 群聊消息身份采用固定层级：头像 → 群昵称 → `wxid` → 时间 → 消息正文；左侧会话列表同步展示群头像、群 ID 和最近消息，右侧身份卡支持核对当前发送者。
- 设置拆成四个任务型分区，避免在一张长页面中堆叠所有表单。
- 模型、备份、更新等高风险流程在弹窗中解释影响和自动恢复策略。

## 文件说明

- `screens/`：39 张 PNG 设计稿，主尺寸 1600×1000，另含 1080×680 压力适配稿。
- `prototype/`：可在浏览器打开的静态高保真原型源文件。
- `设计稿总览.html`：按页面、弹窗和下拉分类浏览全部设计稿。
- `导出设计稿.ps1`：重新渲染和导出 PNG 的一键脚本。

这些文件是设计交付物，不会读取机器人数据，也不会启动、停止或修改现有机器人。
