# 微信群激活码授权服务

付费授权由管理员核实客户后人工发码：月付 **69 元**、年付 **699 元**。客户可在管理器连接微信后自行激活 **1 小时**免费试用，原人工试用码及历史仍保留。客户通过管理器中的微信群二维码联系管理员，没有在线收款接口、短信登录或自动扣款。授权入口使用 `https://ss.xiuxianjyj.xin/wechatrebot-license`；实际可用性以部署验证为准。商业包启用前须完成真实配置和验收，不能将本地测试当作已经开放收费。

本目录是独立服务端，不应打包进客户管理器或运行时。它复用 `wechatrebot_manager.licensing.protocol` 的套餐、日历周期、Ed25519 请求与凭证格式，不使用更新签名私钥。服务端无需微信或机器人进程。

## 用户闭环

免费试用不需要群主发码：未激活且授权服务已配置时，可先连接微信读取实际账号，但不能启动自动化。管理器查询资格后，客户点击“激活免费试用”；服务端在一个写事务内检查物理设备、安装签名身份及微信账号历史并绑定实际账号，成功时开始连续 3600 秒。客户仍需明确启动自动化。暂停、退出、离线和重装都不会延长截止时间，到期提示“你的试用已结束，可联系群主购买”。

同一物理设备和同一微信账号在原试用未到期时可以恢复原授权；重装后允许轮换安装签名密钥，保留授权编号及原截止时间。原设备换账号、原账号换设备均不能新领或恢复；只有设备和账号都从未试用才可新领。同账号跨设备查询已到期试用显示结束状态，但不返回旧设备授权详情。激活响应丢失后重试可恢复原授权，不能重新开始计时。有效付费授权拒绝领取试用；已到期付费授权且双方无试用历史时可明确领取首次试用，接受新签名凭证后也不自动运行。

付费及原人工发码流程如下：

1. 客户从管理器查看套餐并用微信扫描当前有效的群二维码。二维码从授权服务读取，管理员替换后下次刷新即可显示；过期时停止展示图片并提示刷新。管理员按固定客户参考号核实试用资格或人工交易，通过私密渠道交付一个激活码，记录码编号；不把码贴到公开群公告。
2. 客户输入激活码，客户端签名请求预览。预览显示新开通、续期、补领或迁移，以及预计有效期；此时不消耗码。
3. 客户确认兑换。服务器在一个 SQLite 事务中消费码、写入权益和绑定设备，随后签发凭证。首次兑换开始计时，未绑定微信时仅允许连接、读取实际登录账号，不能执行业务。
4. 客户确认实际微信账号后绑定。服务器签发包含该账号的新凭证；管理器和运行时各自验证，客户再选择启动自动化。
5. 运行中定期刷新，客户端执行前及发送前检查。到期暂停自动化，保留微信、配置和数据。到期后的有效签名仍保留真实截止时间，不能靠重启或断网再获得 24 小时。
6. 客户从微信群领取针对原授权编号的续期码。兑换更新同一个 `license_id`，验签落盘后客户明确恢复；不自动启动、不补发暂停期间任务。

## 管理方式

运行环境为 Python 3.13，以及本目录 `requirements.txt` 中固定的依赖。以下是服务器本地管理命令说明，不会自动部署、上传客户包或执行支付。必须在仓库根目录调用模块；模块入口自行定位共享的 `src` 协议实现。

所有命令都使用 `python -m services.activation_service --data-dir <服务器私有目录> <子命令>`。服务账号应独占该目录：Unix 目录权限为 0700，私钥文件 0600；Windows 应由管理员为专用账号配置目录 ACL。不要使用客户安装目录、静态站点目录或版本库目录存储数据库/私钥。

| 子命令 | 必需参数 | 行为 |
| --- | --- | --- |
| `init` | 无 | 首次创建数据库和独立授权私钥，只输出 `key_id` 和公钥等配置；拒绝覆盖已有私钥 |
| `serve` | 无 | 默认监听 `127.0.0.1:8091`，仅开放客户 API；反向代理负责 HTTPS |
| `set-contact` | `--image`、`--group-name`、`--expires-at` | 校验并原子替换固定的微信群二维码资料，下一次 GET 即生效 |
| `clear-contact` | 无 | 仅移除固定二维码资料；不改变数据库、授权、激活码或签名私钥 |
| `issue` | `--owner-ref`、`--reference`、`--plan trial/month/year` | 发新开通码；试用从首次兑换起恰好 3600 秒 |
| `renew` | `--owner-ref`、`--reference`、`--license-id`、`--plan month/year` | 发原授权续期码；不能解除停用状态或更换设备 |
| `recover` | `--owner-ref`、`--reference`、`--license-id` | 发当前设备补领码；不延长有效期、不授予其他设备权限 |
| `migrate` | `--owner-ref`、`--reference`、`--license-id`、`--device` | 核实购买者后发绑定目标指纹的迁移码；可通过 `--reset-account` 明确允许重新绑定微信 |
| `revoke` | `--license-id` 或 `--code-id` 二选一 | 停用授权，或撤销尚未兑换的码；撤销已兑换权益必须使用授权编号 |
| `inspect` | 可选 `--owner-ref` 或 `--license-id` | 查看权益和码状态，不返回激活码、设备私钥或原客户参考号；不指定筛选时只返回数量 |

`--owner-ref` 是人工核验后的稳定客户身份，例如内部客户编号。数据库只保存其规范化哈希；同一客户每次必须使用相同参考号，不能用每次变化的订单号代替。读取二维码不提交微信身份或聊天内容；绑定授权时提交用户已确认的机器人微信账号标识。`--reference` 是唯一人工业务编号，同一编号拒绝重复发码；纯人工流程下，管理员仍须核实业务编号确实对应唯一交易或服务申请。

**自助试用的 `--owner-ref` 固定为激活时实际微信账号标识（例如 `wxid_customer`），不是昵称、群名或人工订单号。** 客户购买后，管理员核实本人及原授权编号，以该微信账号作为 `--owner-ref` 调用现有 `renew --license-id <原授权编号> --plan month/year --reference <唯一业务编号>`，在原授权上转为付费；不要给同一试用另发 `issue` 新开通码。`inspect --owner-ref <微信账号>` 可定位这份记录。原人工码继续使用原固定客户参考号，不能因新入口改写历史。

试用已到期且重装后安装私钥已丢失时，自助恢复不会重新发放试用；管理员需先核验身份，针对新安装指纹明确执行原授权迁移，再用同一授权编号续期转为付费。任何已执行人工迁移的试用都不再接受自助恢复，后续恢复由管理员处理，避免旧物理设备凭历史记录把授权抢回。原物理设备和微信试用历史始终保留。

人工迁移授权的是管理员核验的目标安装公钥指纹，不等于自动确认或登记目标电脑的物理设备身份；原硬件记录也不会被迁移覆盖。此人工授权路径需由管理员核验目标设备，不能宣称新电脑已由服务自动完成硬件关联。

二维码图片仅接受不超过 512 KiB 的 PNG 或 JPEG。`set-contact --image <图片路径> --group-name <群名称> --expires-at <有效期>` 复用共享二维码校验及原子 JSON 写入，只写 `--data-dir` 下固定的 `wechat-contact.json`，不会初始化或打开授权数据库。`clear-contact` 仅删除这一个文件，重复清空也成功。更新二维码无需重启服务或更换签名私钥；操作失败时保留此前资料。

`--expires-at` 接受带时区的 ISO 8601 时间，例如 `2026-10-16T00:00:00+08:00`；日期形式 `2026-10-16` 明确表示 **北京时间 2026 年 10 月 16 日零点截止**，适用于图片标注的“2026-10-16 前有效”。不接受含时分但不含时区的时间，也不能设置已经到期的截止时间。若二维码标明其他截止时刻，应按真实时刻设置，不能通过修改资料日期延长微信本身的二维码有效期。

所有发码命令支持 `--valid-days`（默认 30，范围 1～365）：这是未兑换码的兑换期限，不是已兑换订阅的有效期。激活码为 160 位安全随机数，明文只在生成时显示一次；数据库仅存摘要。应在受控终端将码交给客户并保存业务编号/码编号。未兑换码遗失时先按码编号撤销，再使用新业务编号补发；已兑换码遗失时查出原授权并使用补领或迁移流程，不能再发一个新开通权益。

付费授权重装后设备私钥丢失，需要 `migrate`，不能只凭旧激活码抢占授权。管理员从客户管理器读取新设备指纹并核实购买者身份，再签发针对该指纹的迁移码。默认保留微信账号；确实换微信时才使用 `--reset-account`。旧设备随后无法刷新，但其先前有效的离线凭证最多还能使用 24 小时且不得超过订阅截止时间，这是离线可用性的明确边界。免费试用只允许上述同物理设备、原账号、尚未到期的自助恢复，不获得新的时长。

新电脑已经领过试用或保留着已到期授权时，只有同一客户的、绑定该新设备指纹的迁移码可以替换它。预览会明确返回将被停用的本机授权编号与迁入的原授权编号；客户再次确认后，在同一事务内停用本机旧授权并迁入原授权，保留原到期时间和试用历史。不同客户、不同设备、被管理员停用的授权或仍有效的付费授权均不能直接替换，应由管理员核实处理。迁移不合并两份时长。

## 期限与恢复规则

- 试用历史按客户、安装签名设备、物理设备和绑定的微信账号分别记录，重发码、重装和补领均不重置。物理设备标识来自 Windows 原生读取的 SMBIOS 系统 UUID，客户端仅发送带领域前缀的摘要，服务端再次散列后保存。缺失、占位或无法读取身份时拒绝领取，不回退为随机新设备。该标识用于正常安装和重装的一致性，不是抵抗恶意客户端或固件伪造的硬件证明。历史人工试用若从未记录物理身份，只允许原安装签名与已绑定账号匹配时补登记；安装签名已丢失且历史未登记物理身份，服务端不能反推出原硬件。
- 人工试用新开通码也必须在预览和首次兑换时提供 `machine_id`，两步均检查同一试用历史，兑换事务同时登记物理设备；重装、换账号并重新领人工试用码不能绕过设备限制。缺少设备身份的旧客户端需更新后领取。付费码、已兑换原码恢复和已有授权续期仍兼容无设备身份的请求，硬件读取失败不能阻止购买或续期。
- 新月付/年付从首次成功兑换起按北京时间日历月/年计算。月底保留原锚定日，例如 1 月 31 日开通、2 月 28 日后续期可回到 3 月 31 日；已到期续期从兑换时间重新起算。提前升级试用则接续未用完的试用时间。
- 补领/迁移保留原 `valid_until`，即使已经到期也不赠送时长。续期保持 `license_id` 和已有账号/设备绑定。已撤销授权不能普通续期恢复。
- 预览有效 5 分钟并绑定设备、码、目标授权及其 `revision`；迁移替换还绑定本机旧授权及其 `revision`。期间有续期、绑定或迁移等变更须重新预览。首次开通的预计截止时间会随真正兑换时间顺延，界面应标为预计时间。
- 同设备重复兑换已用码只恢复当前原权益，不再加时；换机后旧设备及已流出的旧码均不能重新抢占。码的兑换期限届满，不影响已经兑换的订阅。
- 权益事务先提交，再签发凭证。响应丢失或签发失败后，可用新签名请求重复兑换原码/预览，或刷新已知授权。不要把码退回可消费状态。
- 迁移替换会持久记录被替换的授权编号。响应丢失后，即使客户端仍缓存着刚被停用的旧编号，仍可用同一迁移码恢复已迁入的原授权；该例外只接受此次兑换确实替换的那个编号，不允许任意切换其他授权。
- 每份凭证最多 24 小时，且不得超过订阅截止时间。刷新过期/撤销权益仍返回签名状态供客户端准确显示；服务不可用、无权限和未激活分别报错，不伪装为欠费。

## API

公开接口是 `POST /v1/preview`、`/v1/redeem`、`/v1/refresh`、`/v1/bind`、`/v1/trial-status`、`/v1/trial-claim` 和只读的 `GET /v1/contact`，`GET /health` 仅用于存活检查。没有公网管理员接口，二维码不能经公网写入或清空。

所有 POST 接口统一使用共享 `sign_request` 信封：`action` 等于路径末段，包含 `body`、服务器时间附近的 `timestamp`、随机 32 位十六进制 `nonce`、设备公钥和设备签名。允许时间误差 ±300 秒；同设备 nonce 保留 601 秒，SQLite 持久化阻止重放。禁止重复 JSON 字段和非有限数字；请求体上限 16 KiB。

| action | body | 成功 data |
| --- | --- | --- |
| `preview` | `{code, license_id?, machine_id?}` | `{preview_id, expires_at, plan, mode, valid_until, license_id, replaces_license_id, already_redeemed, message}`，普通兑换的 `replaces_license_id` 为空；新试用必须提供 `machine_id` |
| `redeem` | `{code, preview_id, machine_id?}` | `{lease}`；新试用首次兑换必须提供 `machine_id` |
| `refresh` | `{license_id}` | `{lease}`，包括过期和撤销状态 |
| `bind` | `{license_id, account}` | `{lease}`，首次真实微信绑定后账号不再普通更改 |
| `trial-status` | `{account, machine_id}` | `{state, eligible, recoverable, account, valid_until, remaining_seconds}`；只读资格，不占用试用 |
| `trial-claim` | `{account, machine_id}` | `{lease}`；原子创建或恢复原试用，签名凭证绑定账号与安装公钥 |
| `GET /v1/contact` | 无，无需设备或激活码 | 当前二维码 record 或 `null`；响应顶层另有 `server_time` |

成功为 `{ok:true,data:{...}}`，失败为 `{ok:false,error:{code,message}}`。`lease` 是 Ed25519 信封，包含当前 `request_nonce`，客户端应核对请求关联、设备、授权编号、版本高水位和截止时间。`account` 为空表示设备已激活但尚未授权任何微信业务。

`trial-status.state` 为 `eligible`、`active`、`ended`、`used` 或 `paid`。资格响应仅供界面显示，不能授权运行；领取接口必须在写事务中重新检查。`machine_id` 为 64 位小写十六进制摘要，由管理器内部读取物理设备生成，不接受界面任意指定。普通管理器状态轮询只读取本地签名凭证，不联网查询试用资格。新增物理设备历史复用 `trials` 表的 `kind=machine`，无数据库结构升级，不删除既有历史。

二维码响应为 `{ok:true,data:record或null,server_time:服务器UTC秒数}`。record 固定包含 `schema_version:1`、`group_name`、`expires_at`、`mime_type`（`image/png` 或 `image/jpeg`）及 `image_base64`，整个响应上限为 768 KiB。缺少资料或已清空时返回 `data:null`；坏资料返回 HTTP 409、`contact_invalid`，不伪装为未配置。有效格式的过期资料仍携带原截止时间，客户端据 `server_time` 显示到期并隐藏图片，不能继续展示旧二维码。这个时间字段仅用于公开联系方式的期限显示，不授予或延长订阅。

`/v1/contact` 每次读取固定文件，不接受请求指定文件路径，不缓存旧图片。它与其他接口共用 socket 来源限流、错误边界和 `Cache-Control: no-store`。反向代理若使用上述授权前缀，应将 `/wechatrebot-license/v1/contact` 转到本服务的 `/v1/contact`，并保留 `no-store`。

常见错误为 `code_unavailable`、`code_expired`、`code_stale`、`preview_required`、`preview_stale`、`trial_used`、`license_unavailable`、`license_revoked`、`active_license_conflict`、`subscription_expired`、`account_bound`、`account_unavailable`。签名/重放错误 HTTP 401；业务冲突 HTTP 409；过大请求 HTTP 413；限流 HTTP 429；服务异常 HTTP 503。客户端不能依据一条未签名错误延长授权或放行。

## 运行与维护边界

部署顺序必须先更新授权服务，再分发新版管理器。新版管理器的激活码预览会附带 `machine_id`；旧服务会拒绝这一额外字段，连付费码预览也不兼容。应先在隔离服务验证新增试用接口与原付费预览、兑换、续期，再更新线上服务并核验协议兼容，最后交付客户端。此处仅说明部署依赖，源码和本地测试完成不代表线上已更新。

SQLite 开启 WAL、外键、FULL 同步和 `BEGIN IMMEDIATE` 写事务，适用于单台服务器的初期人工销售。每次请求独立连接，通过线程执行数据库访问以避免阻塞 aiohttp 事件循环。扩展到多主机前需要明确的数据迁移和事务方案，不能共享网络文件系统上的 SQLite。

数据库结构版本 2 增加迁移替换关联。首次打开版本 1 数据库时，在一个事务中升级字段并保留已有码和预览；未知结构版本拒绝打开。升级前仍应保留一致的数据库备份。

限流使用 socket 实际来源，不信任客户端伪造的 `Forwarded` 或 `X-Forwarded-For`。每个来源默认每分钟 120 次，token bucket 状态以 IP 哈希持久化，最多 4096 个活跃来源，旧记录会清理。在 HTTPS 代理后，服务端看到的是代理 IP；代理必须额外按真实客户 IP 限流，并按实际并发量设置服务 `--rate-per-minute`。不能简单信任任意转发头来绕过这个边界。

只允许 HTTPS 公网入口，内部端口应仅监听回环或受限私网；配置同步时开启可信 NTP。访问日志默认关闭，异常仅记录类型，禁止记录请求体、激活码、签名、私钥及模型密钥。业务审计记录发码、兑换、绑定、撤销，不记录客户聊天。应配置进程托管、监控、磁盘余量预警及定期数据库快照；运行中的 SQLite 应通过其在线备份机制生成一致快照，不能只复制主数据库而漏掉 WAL。

数据库、授权私钥和部署配置需要受控备份。恢复旧数据库快照可能回滚兑换或撤销记录，必须从业务审计核对恢复点后的交易后再恢复发码。密钥轮换需要先让客户端信任新公钥，再切换服务签名；不得直接替换私钥导致所有旧客户端失去验证能力。

商业包须在源码 `src/wechatrebot_manager/licensing-channel.json` 中固定 `enabled: true`、真实 HTTPS 服务地址和独立授权公钥，再通过项目完整载荷流程构建。微信群二维码由服务端固定资料动态提供，可单独更新。商业包忽略安装目录的 `config/licensing.json`，避免普通本地配置关闭授权；该覆盖文件仅供默认未启用包的开发联调使用。
