# 1.0.14 累计维护发布

线上基线：1.0.13；目标：1.0.14，可选完整在线更新。统一收录本轮启动、更新、配置和插件修复，不逐项发布。

## 用户可见变化

- 微信登录确认保留本次启动意图；用户点击“已登录，继续”后继续启动，避免旧轮询将界面恢复为未启动。登录确认不被背景点击或 Escape 隐式取消，重复点击按一次处理。
- 更新关闭回调绑定当前任务代次，旧回调不再干扰新的更新；备份校验使用实际归档字节，避免并发写入造成假损坏。
- 语音及情感关系专属页将未保存和保存中状态传到管理器；离开前确认草稿，保存中阻止刷新、重载、安装更新和恢复备份。删除人格、备份及学习内容增加目标明确的确认。
- 修复百度联网搜索配置映射、视频音频模型优先级、语音配置保存重置运行限制，以及清空记忆后旧摘要回写。
- 微信连接注入器持续读取两路输出，保留有界脱敏诊断；原生工具可使用经验证的 ASCII 路径别名。服务退出报告关联附近日志并保留原退出信息。

## 发布范围与复用

管理器和插件沿用现有配置、授权、事务更新及回滚实现。未新增第三方依赖、插件或原生 HOOK 二进制。相对线上 1.0.12 完整载荷，AstrBot 微信核心补丁还包含已合入的思考标签清理和重试结果保留修复；1.0.13 仅替换管理器，因此本次必须交付完整载荷，不能用遗漏核心源码的管理器或插件差异包替代。运行时由固定 Python、FFmpeg 归档和锁定 wheel 缓存重新组装，应用当前补丁；不编译新的第三方原生依赖。构建器新增主核心及出站策略补丁指纹检查，拒绝复用过期运行时。

发布产物包含完整更新 ZIP、Inno Setup 标准在线安装器及配套 WRB；版本化资产先通过公网完整下载、大小和 SHA-256 校验，再切换 stable 清单。1.0.12 和 1.0.13 使用完整默认更新包，保留用户配置。回滚目标为 v1.0.13 的稳定清单，安装事务沿用原有文件回滚。

## 验证与验收记录

各主题保留独立 PR 审查记录；累计候选执行 GitHub Windows 完整 CI，包括 pytest、浏览器交互、发布元数据和冻结管理器自检。发布前必须确认最终候选对应已合入 master 的提交且 CI 通过。按用户本轮速度要求，不在本地启动机器人或执行全量测试。

用户已明确授权本次线上完整发布和实际 NotSigned 交付，不再等待逐次确认。Ed25519 更新清单签名继续保留，不能将其称为 Authenticode。未执行的真实微信、干净 Windows、Defender 及第二种安全软件验收继续如实标记未完成，现有许可审核未因此改为已批准。

构建固有自检、release_guard、载荷完整哈希、公网下载冒烟以及隔离升级/事务回滚验证保留。实际执行结果、最终 master SHA、产物版本与摘要、发布时间及前一稳定清单归档于本次 artifacts 的发布收据和验收记录；本文件本身不声明尚未执行的步骤通过。源代码交付与许可证文件随完整载荷提供。
